Latency 클록의 지연

  • 클록 신호가 전달되는 과정에서 생기는 시간적 지연 (소스 → 내부 레지스터까지 모든 지연 포함)
  • Source Latency: 칩 밖 클록 소스에서 칩까지의 지연 (이 설계: 0.2 ns)
  • Network Latency: 칩 내부, 입력 포트 → 첫 플립플롭까지의 지연 (이 설계: 0.2 ns)
set_clock_latency -source -max 0.2 [get_clocks MAIN_CLOCK]
set_clock_latency -max 0.2 [get_clocks MAIN_CLOCK]
리포트: Src Latency 200 + Net Latency 200 = Launch 도착 400 ps, Capture 도착 8400 ps. 두 값이 launch와 capture에 똑같이 더해져서 setup slack은 변하지 않는다.

Uncertainty 클록의 불확실성

Uncertainty = Skew + Jitter + Margin → 0.10 = 0.06 + 0.02 + 0.02

  • Skew: 각 Reg가 클록을 인지하는 시점의 차이. 세 요소 중 가장 높은 비중 (±30 ps = 60 ps)
  • Jitter: 클록 신호 위상의 미세한 변동. 이상적인 클록 대비 실제 신호가 시간축상으로 빠르거나 늦게 도착해 좌우로 흔들려 보임 (20 ps)
  • Margin: 설계/제조 오차에 대비한 추가 여유 시간 (20 ps)
set_clock_uncertainty -setup 0.1 [get_clocks MAIN_CLOCK]
리포트: Uncertainty − 100 ps가 Required Time에서 그대로 빠졌다 (8400 − 110 − 100 = 8190).

Transition 클록의 기울기

  • 신호가 0→1 또는 1→0으로 바뀔 때 임계(Threshold)까지 걸리는 시간
  • 길면 신호 왜곡·타이밍 오류 가능 → 짧을수록 상대적으로 유리
set_clock_transition 0.1 [get_clocks MAIN_CLOCK]
리포트: 클록 핀 uut6/r_ibrd_reg_0/CKN의 Trans 100 ps. 이후 데이터 경로 셀의 Trans는 63~276 ps로 셀마다 다르다.
